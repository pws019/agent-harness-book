# Day 1 实践任务

今天不写代码，只写文档，但这两份文档会成为接下来 29 天的地基——不要敷衍。

## 任务 1：选定毕业项目

建议：**"企业知识与代码调查 Agent"**——先只做只读调查，后面阶段再逐步加入受控的写操作（Day15 起）。如果你有更贴近自己实际工作的想法也可以，但要满足：

- 有明确的、可验证的"完成"标准（不是"回答得体"这种模糊标准）。
- 既有需要模型判断的开放式部分，也有能用确定性代码兜底的部分（否则六维框架里"策略"那一维没内容可写）。

## 任务 2：写两套设计方案

在 `product-scope.md` 里，针对你选的项目写两套方案：

- **方案 A：固定工作流**——列出具体步骤（可以画流程图/列表），假装完全不用 Agent loop，纯脚本能不能把这件事做完。
- **方案 B：Agent loop + 工具 + 策略**——用 [study.md](./study.md) 第 4 节的判断清单（开放度、错误代价、可测试性、权限、成本）逐条对比方案 A 和方案 B。

## 任务 3：写 ADR-001

新建 `docs/adr/001-agent-vs-workflow.md`，格式建议：

```markdown
# ADR-001: Agent vs Workflow

## 背景
（一两句话说明要解决的问题）

## 考虑的方案
- 方案 A：...
- 方案 B：...

## 决策
选择方案 X（或方案 A/B 的混合），因为……

## 权衡与代价
（选了这个方案要付出什么代价，明确写出来，不要只写好处）
```

## 任务 4：写任务清单

列出：
- 10 个这个 Agent **应该**能完成的真实任务
- 5 个应该**明确拒绝**的任务（比如超出权限范围、风险过高）
- 5 个**需要人工确认**才能继续的任务

每一条都要写清楚"怎么判断这条任务算完成/算被拒绝/算需要确认"——这是为了避免以后验收的时候变成"我觉得看起来不错"。

## 任务 5：填六维定义框架表

仿照 study.md 第 3 节的表格，为你自己的毕业项目填一遍「目标、环境、能力、状态、策略、完成条件」六个维度，每一维必须给具体、可执行的描述，不能写空话（比如"策略"不能只写"要安全"，要写清楚具体是什么规则）。
