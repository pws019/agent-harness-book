# Day 6・生命周期、取消与并发

> 阶段：I. 最小但正确的内核　|　产出：`src/core/agent-handle.ts`（`Agent`）

## 今天要学会什么

1. 理解 Agent 句柄、运行所有权、inbox、取消这些概念，以及它们为什么必须显式建模，不能靠"程序员自己小心"。
2. 理解取消不是一个布尔值，而是需要跨模型流、工具执行一路传播下去的协议。
3. 理解"每个会话单 writer"：新消息进 inbox 排队，不直接打断当前请求。
4. 理解 dispose 为什么必须幂等，以及"谁创建、谁负责释放"这条所有权规则。

## 怎么学

1. 读 [study.md](./study.md)——这一天我们真实踩到了两个坑（一个是 Day6 自己的设计问题，一个是 Day3 深冻结埋的雷，直到今天才被暴露出来），比任何文档描述都更能说明"取消不是布尔值"这句话的分量。
2. 读 `mini-harness/src/core/agent-handle.ts`。
3. 做 [exercise.md](./exercise.md)：写一次"取消/发送消息"竞态测试，重复 100 次验证不产生悬挂状态。

## 验收标准

- 竞态测试（cancel 和 send 交替、重复 100 次）稳定通过，不出现悬挂 Promise、重复终态记录或遗留资源。
- 你能解释：为什么 `whenIdle()` 不能用来判断"我刚才发的那条消息处理完了没有"？
- 你能解释：为什么深冻结请求对象时，`AbortSignal` 必须被排除在外？
- `pnpm test` 全绿。
