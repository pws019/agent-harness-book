# 毕业项目：只读代码调查 Agent

## 任务 1：项目定义

**名称**：代码库调查 Agent（Repo Investigator）

**一句话描述**：给定一个本地代码仓库路径 + 一个自然语言问题（比如"auth 模块的调用链是什么""这个项目里哪些地方直接操作数据库，有没有绕过 ORM 的"），Agent 只读地探索这个仓库，产出一份结构化的调查文档（Markdown），并在证据不足时明确标记"阻塞"而不是编造结论。

**为什么满足练习要求的两个条件**：

- **完成标准可验证**：产出物是一份 Markdown 文档，必须包含"问题定义 / 已读文件清单 / 结论 / 引用的具体代码位置（文件+行号）/ 未覆盖到的部分"这几个固定小节。是否完成，看文档小节是否齐全、每条结论是否都能追溯到至少一个文件引用——不是"读起来像不像调查报告"。
- **既有开放式判断，也有确定性兜底**：
  - 开放式（必须交给模型）：下一步该读哪个文件、该不该继续深挖、什么时候证据已经够写结论了。
  - 确定性（写死在代码里）：只注册"列目录""读文件""关键词/符号搜索"三个只读工具，不注册任何写权限；单次调查的工具调用轮次设上限；碰到 `.env`、`*.pem`、`node_modules/**` 等路径直接在工具层拒绝，不依赖模型"自觉不读"。

## 任务 2：两套方案对比

### 方案 A：固定工作流（假装不用 Agent loop）

把"调查 auth 模块调用链"这类任务写成一条写死的流水线：

1. 用 grep/AST 工具找出所有文件名或路径包含 `auth` 的文件（固定规则）。
2. 对每个命中文件，用固定的正则/AST 规则抽取函数定义和 import 关系。
3. 把这些函数按 import 关系拼成一张调用图（确定性算法，比如拓扑排序）。
4. 用固定模板把调用图渲染成 Markdown。

这套流程对**这一类**问题（"给定关键词，找相关文件 + 画调用图"）完全可行，纯脚本、零模型调用也能跑完，而且输出可预测、可单测。

### 方案 B：Agent loop + 工具 + 策略

不预设"要找哪个关键词、按什么规则展开"，而是把"读文件""搜索代码"两个工具交给模型，让模型在每一轮根据已读到的内容自己判断下一步读什么、什么时候够了，Runtime 只负责问模型、执行工具、把结果写回历史、判断轮次是否该结束。

### 逐条对比（study.md 第 4 节判断清单）

| 判断维度 | 方案 A 固定工作流 | 方案 B Agent loop | 结论 |
|---|---|---|---|
| **开放度** | "auth 模块调用链"这种命名规则统一、结构清晰的场景，关键词+AST规则能提前枚举 | "这个项目里哪些地方绕过 ORM 直接操作数据库"这类问题，没有统一命名规则可循，需要先读几个文件、根据内容判断"这算不算绕过"，再决定往哪个方向继续挖 | **方案 B 更适合通用调查场景**——毕业项目要覆盖的是"任意自然语言问题"，不是单一固定问题模板 |
| **错误代价** | 规则漏掉一个文件，是可预期的漏召回，容易补规则 | 模型可能读错文件、读到一半误判"够了"，错误来源是模型判断本身，没法靠补正则修 | 方案 B 需要额外的把关机制（轮次上限、"结论必须带文件引用"的输出格式校验）兜住这份风险 |
| **可测试性** | 给定输入仓库，输出的调用图可以写快照测试 | 同一个问题模型可能选不同的探索路径，只能靠"结论是否有引用支撑""是否覆盖了预设的关键文件"这种事后校验，不能全量快照 | 方案 B 的测试策略必须换成"日志重放 + 结构校验"，不是传统单测 |
| **权限/风险面** | 权限单一：只读文件系统 | 权限也单一：只读文件系统 + 搜索，本项目阶段一样不需要动态调整 | 本维度两方案打平，不是决定因素 |
| **成本** | 一次脚本跑完，几乎零成本 | 每轮都要调一次模型，一次调查可能要 5-15 轮，成本明显更高 | 方案 A 更便宜，但换不来"回答任意问题"的能力 |

## 任务 5：六维定义框架

| 维度 | 具体描述 |
|---|---|
| **目标** | 针对用户给定的一个自然语言调查问题，产出一份符合固定小节结构（问题定义/已读文件清单/结论/文件+行号引用/未覆盖部分）的 Markdown 文档；目标有 `active`（调查中）/`blocked`（关键路径不可读或轮次耗尽仍无结论）/`complete`（结论齐全且都有引用支撑）三态，不是只有"完成/没完成" |
| **环境** | 一个本地代码仓库的只读文件系统快照（不给写权限、不给任意 shell 执行权限）；后续阶段可以替换成远程只读挂载，但业务逻辑不用改 |
| **能力** | 仅注册三个工具：`list_dir`（列目录）、`read_file`（读文件，对 `.env`/`*.pem`/`node_modules/**` 等路径直接拒绝）、`search_code`（关键词/符号搜索）；不注册任何写文件、执行命令、网络请求的能力 |
| **状态** | 已读文件清单、已积累的调查片段（谁调用了谁、在哪一行）、当前轮次计数，全部持久化在会话历史里；调查中断后可以从历史续调查，不用重头开始 |
| **策略** | 单次调查最多 15 轮工具调用，超出仍无结论则标记 `blocked` 并说明卡在哪；每条结论必须附至少一个"文件路径+行号"引用，输出格式校验不通过则视为本轮未完成，退回让模型补充；命中敏感路径直接由工具层拒绝，不依赖模型自觉跳过 |
| **完成条件** | 产出文档的四个必需小节都非空，且"结论"小节里的每一条都能在"已读文件清单"里找到对应引用——由确定性的格式校验代码判断，不是模型自称"我觉得写完了" |
